# AgentReel Local Agent v0.3.0 (Draft Release Notes)

AgentReel v0.3.0 introduces **AgentReel Govern**: organization policy syncing, local pre-execution policy enforcement, remote admin approvals, offline fail-open handling, v2 audit decision uploads, and enforcement diagnostics for Claude Code and Cursor.

## Highlights

### Pre-Execution Policy Enforcement
- **Claude Code (`PreToolUse`)**: evaluates every tool call locally against the cached organization policy before execution. `block` returns `hookSpecificOutput` with `permissionDecision: "deny"` and a clear organization policy message. `flag` and `allow` print nothing, preserving existing behavior.
- **Cursor (`beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile`, `preToolUse`)**: installs and evaluates pre-execution hooks and responds via `cursorHookResponse` with `permission` (`"allow"` or `"deny"`), `user_message`, and `agent_message`.
- **Observe mode safety**: policies in `"observe"` mode never block execution and never trigger approval requests.
- **Fail-open on crashes, fail-closed on evaluation timeouts**: any unexpected exception thrown during evaluation or hook handling still fails open to allow and writes a diagnostic line to `~/.agentreel/agent.log`. If local rule evaluation hits the 50ms deadline, all matches collected so far are preserved; if any `block` or `require_approval` rule was unevaluated or timed out, enforcement fails closed with reason `eval_timeout` and records a `policy_decision` (subject to `observe` and stale `fail_open` modifiers). If only `flag` rules remain unevaluated, the strictest collected result is returned alongside a recorded `eval_timeout` flag.
- **Pause and `AGENTREEL_DISABLE=1` behavior**: `agentreel pause` and `AGENTREEL_DISABLE=1` stop local session recording and capture, while organization policy enforcement remains active on Claude Code and Cursor pre-execution hooks (no capture events are written beyond the `policy_decision` audit records required by enforcement).
- **Expanded built-in detection**: adds `SECRET004` to catch direct reads of `.env` files, SSH keys, AWS credentials, and production credential files, and updates `FS001` to match `rm -rf ~` with or without a trailing slash.

### Remote Admin Approvals
- Rules configured with `action: "require_approval"` invoke the remote approval client (`POST /api/v1/approvals` followed by `GET /api/v1/approvals/:id?wait=25s` long-polling).
- Sends a stable idempotency key (`decision_id`) per decision so retries reuse the same approval, and scrubs `summary` through the local secret scrubber before transmitting.
- `POST /api/v1/approvals` treats `201` (created) and `200` (same-payload replay) identically. A `409` conflict (`decision_id` reused with a different payload) is logged as a client bug and falls back to the rule's effective `offline_fallback` (default `"deny"`), still bounded by the hook/expiry deadline guard.
- Top-level `approval_defaults` (`{ expires_s: 120, offline_fallback: "deny" }`) and optional per-rule `approval` on both builtin overrides and custom rules merge as `rule.approval` over `approval_defaults` over built-in defaults (`120`, `"deny"`). `expires_s` must be an integer in `10..3600` (out-of-range values reject the policy in `validatePolicy`, naming the rule), and the `hook_timeout_too_short` check still applies afterward.
- Both `POST` and `GET /api/v1/approvals/:id` honor echoed `expires_at`, tightening the effective expiry to `min(local expiry, server expires_at)` without ever extending past the local expiry or hook deadline.
- Denies on timeout, expiry, or admin denial; allows only on explicit approval (or when the server is unreachable/failing and `offline_fallback: "allow"` is configured).
- Prints a clear waiting status (`Waiting for admin approval (<rule name>), up to <N>s`) to stderr without corrupting hook stdout JSON.
- Strictly isolated networking: only the `require_approval` path can load the approval client; every other decision path is synchronous and network-free.

### Offline Modes (`last_known` vs `fail_open`)
- `last_known` (default): continues enforcing the cached policy indefinitely when offline.
- `fail_open`: continues evaluating and recording audit decisions, but downgrades `block` and `require_approval` to `flag` with reason `"policy stale, fail_open"` when the cached policy is older than 24 hours (`POLICY_STALE_MS`, clock-skew safe) or no server policy exists.

### Policy Cache, Evaluator, and Performance Hardening
- Fetches `GET /api/v1/policy` with Bearer authentication and `If-None-Match` ETag caching against the single global cache (without sending `?repo=`; per-repo policy caching is a follow-up), atomically writing `~/.agentreel/policy.json` with mode `0600`. On `304 Not Modified`, keeps the cached policy, updates `fetched_at`, clears any `policy.json.rejected.json` sidecar, and logs nothing alarming.
- Accepts `200` no-org payloads (`org_id: null`, `mode: "observe"`, empty `builtin`/`custom`/`allow`) by caching them with no enforcement and reporting `no org policy` in `agentreel doctor` when no org policy is cached, while keeping `404` tolerance unchanged. Once an org policy is cached, normal refreshes ignore no-org responses (`no-org response ignored; keeping cached org policy <org_id>`) and responses for a different non-null org (`policy for org <B> ignored; keeping cached org <A>`), surfacing warnings in `agentreel doctor` (including `run \`npx @agentreel/agent auth\` to switch orgs` on org mismatch). Explicit `agentreel auth`/`link` fetches a fresh policy (no ETag) and atomically replaces the policy cache, ETag, and sidecar only once it validates, so a failed auth or policy fetch keeps the previous cache in force; `agentreel logout` clears them. Accepts additive `org_id` (validated equal to `workspace_id` when both are present; mismatches reject the policy with a clear doctor message), `fetched_at`, and ignores unknown extra top-level fields.
- Supports optional `scope.teams: string[]` alongside `scope.members` as display-only metadata: team filtering happens on the server (with per-caller ETags), so the CLI accepts `scope.teams` in validation, never skips rules based on team membership, always applies delivered rules subject to the other scope fields, and ignores any unknown fields such as `current_user_teams`. Severity remains `info | warn | high | critical` (required on custom rules, optional on builtin overrides).
- Refreshes cached policy every 5 minutes in `agentreel daemon` and once on `agentreel link` and linked `agentreel init`.
- Rejects policies containing unsupported custom regexes during `validatePolicy` (naming the rule ID and condition index), keeping any last-known cached policy untouched (or leaving org enforcement off when no policy is cached yet), logging the rejection, and surfacing a clear warning in `agentreel doctor` (`policy rejected by agent: rule <id> has an unsupported regex; last known policy still in use` when a cache exists, or `policy rejected by agent: rule <id> has an unsupported regex; the rejected policy was not installed and org enforcement is off until a valid policy is cached` on a first fetch with no cache). As defense in depth, if a cached policy ever contains a regex that fails to compile during evaluation, enforcing rules (`block` or `require_approval`) fail closed with reason `invalid_rule` and `flag` rules record an `invalid_rule` flag instead of being silently skipped.
- Adds a bounded 256-entry regex compile cache, deterministic evaluation ordering (built-in rules and cheap matchers before regex rules, and enforcing regex rules before `flag` regex rules), and a 50ms total local evaluation deadline that preserves collected matches and fails closed when enforcing rules are unevaluated.
- **Supported custom regex subset**: patterns are capped at 300 characters and must stay inside a linear-time RE2-safe subset with no lookarounds, no backreferences, no `\p{...}`, `\P{...}`, `\cX`, octal escapes (`\0` followed by a digit, outside or inside `[...]`; plain `\0` remains a NUL literal), or malformed hex/Unicode escapes, no nested quantifiers, and no quantified alternations (`(a|aa)+`, `(a|a?)+`, `(x|xy)*`). `\xHH`, `\uHHHH`, and `\u{H...}` escapes are decoded as single characters both outside and inside `[...]`. Multiple unbounded quantifiers (`*`, `+`, `{n,}`) are allowed only when the pattern begins (after an optional `^`) with at least one mandatory literal or literal-only bounded token (including a literal-only alternation group such as `(DROP|TRUNCATE)`) before the first unbounded quantifier, the last character set of that leading literal run (or the possible last characters of a literal-only group) is disjoint under ASCII case folding from the first unbounded quantifier's atom, and every consecutive pair of unbounded quantifiers is separated by a mandatory (non-optional, non-zero-repeat) literal or character class whose character set cannot match either neighbor (or directly adjacent when one side is mandatory whitespace `\s+` and the two sides are disjoint). Single-unbounded patterns (such as `curl[^|]*\|`) are unaffected by the leading-literal rule. For example, `rm\s+-rf\s+/`, `curl\s+\|\s*sh`, `curl\s+\S+\s+\|\s*(ba)?sh`, `(DROP|TRUNCATE)\s+TABLE\s+\w+`, `aws\s+s3\s+rb`, and `^git\s+push\s+--force` are accepted, while unprefixed, octal, or overlapping patterns such as `\w+\s+\w+`, `\S+\s+\S+`, `[a-z]+@[a-z]+`, `a+\s+b+`, `A\w+\s+\w+`, `\x41\w+\s+\w+`, `a[a-z]+\s+\w+`, `(DROP|TRUNCATE)\w+\s+\w+`, `\012+\s+\w+`, `\x41+\x42+`, `curl[^|]*\|\s*(ba)?sh`, `curl.*\|\s*(ba)?sh`, `.*passwd.*`, `kubectl\s+delete\s+.*prod`, and `\w+\s*\w+` are rejected. Tip: avoid `.*` before a literal (prefer `curl\s+\S+\s+\|\s*(ba)?sh` or single-unbounded `curl[^|]*\|` instead of `curl.*\|\s*(ba)?sh`, because `.` overlaps `|`, and unanchored `curl[^|]*\|\s*(ba)?sh` is rejected because `l` overlaps `[^|]`).

### Audit Trail (`policy_decisions` v2)
- Writes every non-allow policy decision locally as a `policy_decision` event (`id`, `ts`, `session_id`, `rule_id`, `rule_ids`, `action`, `enforced`, `downgraded`, `policy_etag`, `tool`).
- Uploads decisions in the existing session ingest batch under `policy_decisions` (`version: 2`) next to `guard_findings` (`version: 1`), which remains unchanged and backward compatible.

### Hook Timeouts and CLI Commands
- `agentreel init` idempotently sets longer timeouts (130s by default, or max rule expiry plus 10s) only on hooks that can reach `require_approval` (Claude `PreToolUse` and Cursor `preToolUse`, `beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile`). Other hooks keep their 5s timeout.
- `agentreel policy` displays policy source, ETag, clock-skew-safe cache age, mode, offline setting, and rule/allow counts.
- `agentreel doctor` reports enforcement readiness: whether a policy is loaded, active mode, ETag age, and whether pre-exec hooks are installed with the expected timeouts.

## Upgrading

You must re-run `npx @agentreel/agent init` after upgrading to 0.3.0 so approval rules work. Upgrading without re-running `init` leaves the legacy 5s hook timeout in place, which causes `require_approval` rules to deny with a prompt to run `npx @agentreel/agent init`. Re-running `init` registers the new Cursor pre-execution hooks, updates pre-execution hook timeouts to 130s (or max rule `expires_s` plus 10s), and records the installed timeouts per host in `~/.agentreel/config.json`. Run `agentreel doctor` afterward to verify your setup.

### Changed: now rejected regex patterns

The stricter RE2-safe regex subset rejects these multi-quantifier patterns that earlier builds accepted. Update any custom rules using them to these verified replacements:

- `curl[^|]*\|\s*(ba)?sh`: use `curl\s+\S+\s+\|\s*(ba)?sh`, or the single-unbounded `curl[^|]*\|`.
- `(curl|wget)[^|]*\|\s*(ba|z)?sh`: use `(curl|wget)\s+\S+\s+\|\s*(ba|z)?sh`.
- `\w+\s+\w+`: add a leading literal whose last char is disjoint from `\w`, e.g. `git\s+\w+\s+--force`.
- `\S+\s+\S+`: add a leading literal disjoint from `\S`, e.g. `rm\s+\S+\s+/`.
- `\u{1F600}\s+\w+` (non-ASCII literals are now treated as overlapping every character): use `\u{1F600}\s+\w`, which matches the same commands because rules match anywhere in the input.
